01 · How it works

Understand one connection without jumping between different tools.

HypNO brings the main investigation steps into one place. Specialist tools still have their own strengths.

Survey what connected. See the app, process, service, connection direction, protocol, and ports.

Correlate what Windows says created it. Check the process, file path, publisher, digital signature, version, and file hash.

Investigate where it connected. Review the network owner, connection history, hostnames, approximate location when available, and packet evidence when needed.

Explain where each answer came from. Keep Windows evidence, local data, outside provider results, and missing information separate.

Decide why HypNO is showing it. See what looks normal, what deserves attention, what is missing, and what to check next.

Enforce a controlled action. Preview exactly what will change, use temporary rules when needed, and keep a way back.

Verify the result. Confirm that the rule worked, access changed as expected, and the previous state can be restored if needed.

Guided learning layer

Learn networking from what your own computer is actually doing. HypNO explains what happened, why it matters, and what you should look at next.

02 · Tools HypNO brings together

These tools each solve a different part of the job.

HypNO brings the parts I use most into one investigation so a new IT technician does not have to learn several separate workflows just to understand one connection.

TCPViewWindows connection viewer

Usually used to quickly see which TCP or UDP connections are open and which Windows process or service owns them.

HypNO: Shows live and ended connections and connects them back to the app, process, and service.

WiresharkPacket analyzer

Usually used when you need to capture packets and inspect network traffic in much deeper detail.

HypNO: Imports PCAP/PCAPNG and organizes packet evidence into IPs and flows. Wireshark remains the deeper packet-analysis tool.

simplewallApplication network control

Usually used to allow or block application traffic through Windows Filtering Platform rules.

HypNO: Gives the user application-level network control, but is designed to work through native Windows Firewall instead of replacing it.

Windows Firewall ControlWindows Firewall management

Usually used to make Windows Firewall rules easier to create, review, and manage.

HypNO: Reads Windows Firewall, explains the rule scope, creates controlled HypNO-owned rules, verifies them, and keeps recovery in the workflow.

PortmasterApplication firewall and privacy

Usually used to watch application connections and control what each application is allowed to reach.

HypNO: Shows application connections and adds investigation evidence before the user decides whether a connection should be blocked.

GlassWireVisual network monitor

Usually used to make current and past network activity easier to see, alert on changes, and block unwanted application traffic.

HypNO: Keeps connection history, application context, alerts, and firewall response together with deeper Windows evidence.

The difference is the workflow.

HypNO is not claiming to replace every advanced feature in these tools. It brings their most useful investigation steps into one place, then explains how the evidence connects.

06 · Investigation tools

Start simple. Open the deeper technical evidence when you need it.

HypNO keeps the technical detail available without making you start with raw packets or long system lists.

  • Application Investigator: Review the exact file path, SHA-256, digital signature, publisher, product, version, processes, services, and related evidence.
  • Evidence strength: HypNO keeps confirmed ownership, strong association, possible association, shared or ambiguous evidence, protected items, and unsupported items separate.
  • Packet capture: Import PCAP and PCAPNG files and organize them into remote IPs, flows, packets, direction, DNS, TLS, protocols, and ports.
  • Validated example: 120,656 packets were organized into 89 remote IPs and 936 flows while keeping the original packet evidence underneath.
  • Recovery-first response: Verify the exact target, save recovery evidence, and confirm the result after an advanced action.
  • Saved cases: Future investigations can keep the alert, evidence, notes, response, verification, and final report together in one record.

08 · Trust and privacy

Know what HypNO checked—and what it could not confirm.

HypNO should clearly show where information came from, when something leaves the PC, and how to undo important changes.

  • Local first: Windows evidence works without any outside account. Local GeoLite can add network-owner and approximate-location information offline.
  • No silent provider lookup: Opening an investigation does not automatically send the IP anywhere. You choose when to use an outside lookup.
  • Credentials stay separate: Saved provider keys stay in Windows Credential Manager and should not appear in reports, logs, the database, or the website.
  • Unknown stays unknown: Missing reports do not mean safe. A signed app can still behave badly. One piece of evidence is never the whole answer.
  • Recovery before power: Before a powerful action, HypNO should save what it needs to undo the change and verify what happened afterward.
  • Honest development: Unfinished features stay labeled unfinished. Failed tests and known issues remain part of the record.
09 · About

Why I built HypNO.

The product came from using several different tools to understand Windows network activity and wanting the entire investigation to be easier to follow.

Origin

The information existed. The workflow didn’t.

One tool showed the connection. Another showed the process. Another showed the packets. Another checked the IP. Another managed the firewall.

HypNO is my vision of starting with one thing and breaking it down clearly and concisely so the user does not need to move between several applications and understand each one before putting the story together.

I am not trying to remove the value of specialist tools. I am building the workflow between them.
