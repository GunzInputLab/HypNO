01 · What HypNO is built to do

From one connection to a decision you understand.

HypNO answers six questions in order so you know what happened, why it matters, and what to do next.

1. What connected?

See the app, process, service, and executable that created the traffic.

2. Where did it go?

See the IP, port, protocol, network owner, and connection history.

3. Is anything different?

Spot new destinations, changed app identity, or behavior that does not match the usual history.

4. What does the evidence say?

Keep Windows facts first, then add optional location, reputation, scanning, or IOC context when useful.

5. What should I do?

Know what is confirmed, what is uncertain, and whether to watch, research, allow, block, or make no change.

6. Did the action work?

If you change Windows Firewall access, verify the result and keep a recovery path.

About

Why I built HypNO.

The product came from using several different tools to understand Windows network activity and wanting the entire investigation to be easier to follow.

Origin The information existed. The workflow didn’t.

One tool showed the connection. Another showed the process. Another showed the packets. Another checked the IP. Another managed the firewall.

HypNO is my vision of starting with one thing and breaking it down clearly and concisely so the user does not need to move between several applications and understand each one before putting the story together.

I am not trying to remove the value of specialist tools. I am building the workflow between them.

Tools HypNO brings together

Each tool is useful. HypNO connects the steps.

HypNO does not claim to replace every advanced feature in these products. It combines the parts commonly needed to understand and respond to one Windows connection.

TCPView

Commonly used to see active TCP and UDP endpoints and the Windows process or service that owns them.

HypNO adds: retained history, executable identity, IP context, explanation, and the next action.

Wireshark

Commonly used to capture packets and inspect protocols in much deeper detail.

HypNO adds: PCAP/PCAPNG organization into IPs and flows. Wireshark remains the deeper packet-analysis tool.

simplewall

Commonly used to allow or block application traffic through Windows Filtering Platform rules.

HypNO adds: an investigation before the decision and native Windows Firewall management instead of a separate filtering model.

Windows Firewall Control

Commonly used to make native Windows Firewall rules easier to create, modify, and manage.

HypNO adds: application evidence, destination context, rule preview, verification, audit, and recovery.

Portmaster

Commonly used to monitor application connections and control what each app can reach.

HypNO adds: deeper Windows executable evidence and a guided investigation before the block decision.

GlassWire

Commonly used to visualize current and past network activity, alert on changes, and control application traffic.

HypNO adds: deeper identity evidence, source-separated IP context, and a recovery-aware Windows Firewall workflow.

Revo Uninstaller

Commonly used to uninstall programs and scan for leftover files, folders, and Windows Registry entries.

In developmentHypNO direction: investigate the connection and application first, verify which artifacts actually belong to it, prepare recovery, use the trusted uninstaller, then review verified leftovers and confirm the unwanted behavior is gone.

04 · Firewall & interactive protection

Understand the rule before you change it.

HypNO is building an interactive Windows Firewall workflow that starts by understanding the policy already on the PC—not by deleting unfamiliar rules and rebuilding from a generic list.

In development

Monitor Only

Read and explain Windows Firewall, build a baseline, watch changes, and make no policy changes. This is the safest starting point while the machine is being understood.

In development

Smart Interactive · Recommended

Keep familiar traffic quiet. When application behavior meaningfully changes, HypNO opens one investigation and lets the user review Monitor, Allow, Block, or a custom native Windows Firewall rule.

In development

Strict Interactive · Advanced

Use a carefully prepared outbound-block posture so unknown traffic is blocked first, then identify the application, review the evidence, create the approved rule, and verify the retry.

Firewall baseline

Know what is already there before cleaning anything up.

HypNO will use Windows rule provenance, application/service ownership, current machine configuration, and the accepted baseline to explain rules. A rule that is absent from a built-in list is not automatically wrong.

Questionable local rules follow a recovery-first path: Review → Disable & Test → Restore or Delete after confirmation.

Windows stays in control.

Group Policy, device-management policy, protected Windows rules, service-hardening policy, and unresolved ownership are preserved rather than silently rewritten.

07 · Built to be trusted

HypNO should tell you what it knows, what it doesn’t, and what it changed.

A network security tool is more useful when the customer can see the source of the evidence and understand the limits of every conclusion.

Core investigation works without providers

Windows connection evidence, process identity, packet-capture investigation, and local context do not depend on an online reputation account.

No silent IP lookup

Opening or importing an investigation does not automatically send captured IPs, domains, hashes, or files to a provider.

Private addresses stay local

Private, loopback, link-local, and other special-use addresses stop before provider reputation access.

Provider failures do not break HypNO

Not Connected, No Record, Rate Limited, Authentication Failed, Provider Unavailable, and policy restrictions stay source-specific.

Unknown stays unknown

No provider record does not mean safe. A signed executable does not guarantee harmless behavior. A data-center IP is not automatically malicious.

Your provider credentials stay yours

The release design keeps provider secrets in protected Windows storage and out of ordinary HTML, SQLite, logs, exports, screenshots, and packaged files.

Windows Firewall remains the authority

HypNO can explain and manage approved native Windows Firewall decisions, but it does not replace Windows with a separate hidden policy engine.

Your antivirus stays independent

Microsoft Defender, Bitdefender, ESET, or another installed antivirus remains a separate protection layer. Supported scan handoff adds AV evidence to the investigation without turning HypNO into antivirus.

Unfamiliar firewall rules are not auto-deleted

HypNO uses Windows provenance, application/service ownership, the current machine state, and a saved baseline before suggesting cleanup. Unknown ownership stays unresolved and preserved.

Organization policy is respected

If Group Policy or device management controls Windows Firewall or auditing, HypNO explains that state instead of fighting it or pretending a local rule is effective.

Windows telemetry is supplemental

Event Log, optional ETW, and performance context can strengthen a case, but core connection monitoring continues when those sources are unavailable.

Recovery is part of the feature

A write-capable action is not complete until it has preview, authorization, verification, audit evidence, and a recovery path.

09 · Common questions

Know what HypNO does—and why that matters.

HypNO is designed to investigate and control Windows network behavior without pretending one signal can prove everything.

Does HypNO protect my applications automatically?
HypNO is not an automatic malware blocker. It helps protect application network access by making unexpected or changed connections easier to investigate and by putting evidence, Windows Firewall scope, verification, and recovery around a response decision.
Is HypNO antivirus?
No. HypNO investigates Windows network behavior. Microsoft Defender or another antivirus remains a separate protection layer.
Does HypNO replace Wireshark?
No. Wireshark remains the stronger specialist for deep packet and protocol analysis. HypNO connects packet evidence to the wider Windows application investigation.
Do I need online provider accounts for HypNO to be useful?
No. Core Windows analysis and Local GeoLite can work without online providers. Connected sources add optional evidence such as web geolocation, reported abuse, scanning context, and IOC information.
Does “No Record Found” mean an IP is safe?
No. It only means that provider did not return a matching record. HypNO keeps that result separate from the application identity, connection history, role, expectedness, and other evidence.
Can HypNO block a connection?
Windows Firewall investigation and HypNO-owned rule control are part of the Windows foundation. The product direction adds clearer scope preview, verification, recovery, drift detection, and native Windows Firewall/Defender acceptance.
What is Smart Interactive?
Smart Interactive is the planned recommended firewall mode. Familiar activity stays quiet, while meaningful new or changed application behavior can open one investigation where the user reviews Monitor, Allow, Block, or a custom Windows Firewall response. It is not presented as holding the first outbound packet for approval.
What is Strict Interactive?
Strict Interactive is the planned advanced mode. Native Windows Firewall uses a carefully prepared outbound-block posture so unknown traffic is blocked first, HypNO identifies the application when the evidence supports it, and the user can allow temporarily, always allow, keep blocked, or investigate further. This remains In development until attribution and rollback testing pass.
Does HypNO delete Windows Firewall rules it does not recognize?
No. HypNO is designed to inventory the firewall, identify rule provenance and ownership, build a baseline, and review questionable local rules. Cleanup follows a recovery-first Disable & Test workflow before permanent deletion is considered.
Can HypNO scan a suspicious application?
The planned scan-handoff workflow can ask Microsoft Defender or another supported installed antivirus to scan the exact executable being investigated. The antivirus result remains a separate evidence source, and a clean result is not treated as proof that the application is safe.
Does HypNO use Windows Event Log or performance data?
The planned Windows Evidence Timeline can translate relevant Event Log, optional ETW, and selective performance context into the investigation. Those sources are supplemental; the existing live connection monitor remains useful if they are unavailable.
Will HypNO eventually monitor more than one Windows PC?
Yes, that is part of the longer-term direction. The Windows product comes first; later network collection, an optional Sensor, and technician/multi-site workflows expand the evidence model outward.
